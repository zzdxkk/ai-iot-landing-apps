# 09 · OTA 固件升级服务

## 解决什么问题
设备装在野外，升级只能远程做。一次传不完、传坏了、升到一半断网，都会把设备变砖。所以升级必须分包、逐包校验、能续传，而且先升一小批看结果。

## 怎么实现
- `chunk_firmware()` / `shard_checksum()`：按 256 字节分包，逐包算 CRC32
- `OTAJob.deliver()`：收到包先校验，不通过直接拒收（可重传），通过才暂存
- `progress()` / `assemble()`：按已收包算进度，收齐后按序拼回固件
- `version_gt()`：语义化版本比较（`v1.2.0` vs `v1.1.9`）
- `canary()`：按比例挑一小批设备先升

## 跑起来
```bash
python3 src/ota.py                          # 分包下发、进度、拼包校验、灰度名单
python3 -m unittest discover -s tests -v    # 6 项
```

## 验证
6 项单元测试覆盖：分包数量、CRC 列表、坏包拒收、进度推进、拼包一致、版本比较与灰度比例。

## 边界
- 没有传输层（HTTP/MQTT 下发、设备端接收），也没有签名验签与回滚机制
- 灰度按设备列表索引切分，不是真实的分组/地域/在线率策略；无并发升级与失败统计
